# YORU 4.14.1 — первый пакет исправлений производительности

Дата: 7 сентября 2026. Исходная версия: 4.14.0, versionCode 56. Новая версия: **4.14.1, versionCode 57**.

Это реализация первого пакета из аудита, не утверждение, что все сторонние источники или все проблемы производительности уже проверены и исправлены.

## Реализовано

### Запуск, UI и данные

- Android Keystore, расшифровка библиотеки и восстановление профиля вынесены в отдельный локальный worker. Activity показывает лёгкий стартовый экран, а не блокирует main thread ожиданием хранилища.
- Удалена обязательная инициализация WebView в native Player.
- Foreground-пул имеет четыре фактически работающих worker-а. Нет `DiscardOldestPolicy`: принятые пользовательские задачи не исчезают молча. Отменённые Future удаляются из очереди.
- Состояние загрузки принадлежит экрану до применения callback в main. Возврат на вкладку не использует отменённый loading-view как готовый экран.
- Коллекция и история отображаются через GridView с переиспользованием карточек, а не создают все карточки в ScrollView. Подготовка списка идёт в worker.
- Исправлено двойное преобразование dp в высоте списка серий; убраны часть повторных render и неизменившихся обновлений списка скачанного.
- ImageLoader заменён на Glide с lifecycle-aware requests, target sizing, memory/disk cache и объединением запросов. Локальные постеры сохранены.
- JSON/AES/запись preferences выполняются последовательным coalescing writer. Прогресс больше не переписывает неизменённые favorites/settings, не пересобирает все индексы и не дублируется каждым tick в SQLite.
- Сохранение обычного playback-progress ограничено десятисекундным интервалом и активным воспроизведением; на lifecycle-событиях выполняется асинхронный flush.
- Календарный JSON перенесён из settings в существующий SQLite-cache. TrafficMeter восстанавливает счётчики; обновления виджета больше не создают новые SecureStore на каждый tick.
- Отрицательные lookups ограниченно кэшируются; сортировки вариантов и приоритетов используют подготовленные оценки. Импорт обновляет индексы.

### Карточка, источники, видео

- Метаданные и подбор серий запускаются независимо. Скриншоты и франшиза больше не блокируют готовые серии и загружаются отдельно.
- Автоподбор возвращает первые подходящие результаты с коротким settling window, вместо обязательного ожидания всех источников. Сохраняется явное действие «Все озвучки / обновить»; если быстрые варианты не сработали, Player может один раз расширить подбор.
- Уже подготовленный граф серий переиспользуется между карточкой, выбором озвучки и Player через ограниченный cache; граф не отправляется большим JSON через Binder.
- Lazy-эпизоды не теряются при объединении источников; сохраняются реальные числовые качества.
- Одновременные одинаковые HTTP/resolve/playback-запросы объединяются. Недавний неуспех не резолвится повторно немедленно.
- Сеть не удерживает общий монитор ApiRepository/YoruShield. Добавлены общий бюджет worker-операции, проверка отмены и закрытие зарегистрированных соединений.
- Плеер помнит уже неудачные variants/qualities: исключены циклы A→B→A и 1080→720→1080. Строгий выбор озвучки не сбрасывается автоматически в Player.
- HLS сохраняет master с audio/subtitle groups; Media3 получает ограничение высоты трека и для HLS, и для DASH. Публичный Referer передаётся в request-specific factories Player и Downloader.
- Ограничены глубина и количество узлов рекурсивного iframe-resolver.
- Поиск серии использует точное совпадение вместо скрытой подстановки ближайшей. Открытие последней серии само по себе больше не означает completed.

### Офлайн, фон, сборка

- Чтение списка скачанного и инициализация его индекса выполняются вне main thread; «индекс ещё не готов» не считается окончательным отсутствием файла.
- DownloadIndex публикуется целиком, без промежутка между clear/putAll.
- BroadcastReceiver передаёт длительную проверку JobScheduler; остановка job отменяет Future. Проверки не конкурируют с открытым Player и не загружают дополнительно весь календарь перед каждым обходом избранного.
- Календарные обращения объединяются и имеют короткий memory-cache. При старте приложения нет обязательной сетевой загрузки календаря.
- Жест/кнопка «Назад» переведены на AndroidX OnBackPressedDispatcher; theme-атрибут API 27 вынесен из ресурсов Android 8.0. Использование Media3 UnstableApi явно оформлено через OptIn, без отключения lint.
- Убрана ссылка настройки сборки на отсутствующий `:yuroguard`. Рабочий CI устанавливает JDK 17/SDK 36 и проверяет тесты, release и lint.
- Добавлены 42 JVM regression tests: очереди, cancellation, coalescing, first-result selection, strict voice predicate, retry history, loading ownership, HLS master, headers, TTL, iframe cycles, snapshots и точный номер серии.

## Следующая проверка на устройстве

1. Установить APK поверх 4.14.0, не удаляя старое приложение и его данные.
2. Проверить коллекцию, папки, историю, настройки и ранее скачанные серии.
3. Сравнить холодный/повторный запуск, быстрые переключения вкладок и прокрутку большой коллекции.
4. Проверить первый/повторный просмотр, другую озвучку, strict mode, смену качества и отсутствующую серию.
5. Проверить offline в airplane mode, PiP, pause/resume, скачивание одновременно с просмотром и уведомления.
6. Если проблема осталась — зафиксировать модель телефона, Android, тайтл/серию, озвучку и тип сети; собрать stage timings и frame trace.
