# YORU VK 0.1.0 — отдельный прототип

Независимое Android-приложение: Shikimori даёт метаданные и постеры, VK API ищет видео по названию, сезону и серии. Не является официальным продуктом ВК, Shikimori или Kate Mobile.

## Что реализовано

- Самостоятельный пакет `app.yoru.vk.prototype`, название YORU VK. Устанавливается рядом с YORU, не заменяет её и не читает её данные.
- Тёмная фиолетовая палитра и нативные карточки на основе YORU 4.19.1. Shikimori GraphQL с REST fallback, как в подходе YORU; лишние источники не перенесены.
- Каталог, поиск с задержкой 700 мс, постеры, описания, рейтинг, число серий, связанные тайтлы/сезоны.
- Пример: «Мастера меча онлайн» → сезон 1 → серия 1 → «Смотреть · найти видео ВК».
- Формируется редактируемый запрос `Мастера меча онлайн 1 сезон 1 серия`. Можно добавить озвучку или выбрать оригинальное название. Фильмы ищутся без номера серии.
- VK `video.search`: релевантность, только видео VK (`filters=vk`), безопасный поиск, 30 результатов за запрос, до 500 в соответствии с ограничением сервиса. Фильтр >10 минут можно отключить для коротких выпусков.
- Результат: название загрузки, изображение, длительность, просмотры, ID автора; результаты не объявляются автоматически правильными сериями.
- `video.get` обновляет сведения по конкретному видео; нативный Media3-плеер играет разрешённые прямые MP4/HLS/DASH из `files`, выбор качества, перемотка, пауза. Нет iframe, внешнего плеера, извлечения скрытых файлов или обхода защиты.

## Вход токеном

Введите только внутри приложения: сырой пользовательский токен, `access_token=…` или полную ссылку VK с параметром в query/fragment. Поддержана URL-кодированная ссылка и кодированные значения. Дублирующиеся, повреждённые, пустые значения и ссылки чужих доменов отвергаются. Ссылка разбирается локально, переход по ней не выполняется.

Токен проверяется через `users.get`. Это подтверждает аккаунт, но НЕ право искать или смотреть видео. Наличие прав `video` проверяется фактическим запросом поиска. Ввод токена от Kate Mobile поддерживается как ввод пользовательского VK access token, а не как отдельный «Kate API».

Никакого пароля, обхода CAPTCHA, получения токена через чужой секрет приложения или имитации клиента Kate Mobile нет. Приложение не выпрашивает расширенные права и не умеет получать токен за пользователя. Не используйте сомнительные генераторы токенов.

## Ограничения VK API

На дату исследования 2026-09-09 публичная документация `video.search` указывает пользовательский токен с правом `video`, выдаваемым приложениям в исключительных случаях. Поле `files` зависит от прямой авторизации. Наличие видео в поиске не означает наличие прямого потока. См. [1](https://dev.vk.com/en/method/video.search).

Методы/параметры сверены также с официальной схемой VKCOM: https://github.com/VKCOM/vk-api-schema/blob/333481bd082ad747d4873ef4a77f9247097eeef0/video/methods.json. Используемая версия протокола — 5.199; это явно выбранная версия, а не заявление «самая новая в 2026».

Страницы документации VK при прямом открытии периодически отдавали технические работы. Поисковая выдача официальной страницы и актуальная схема доступны. Официальный сайт katemobile.ru при проверке ответил HTTP 500; подтверждённый действующий секрет/специальный протокол Kate Mobile не получен и не требуется этому прототипу. Старые советы из форумов 2014–2018 годов не использованы как гарантия работы в 2026.

Если `video.get` не возвращает `files`, приложение честно показывает ограничение. Если ВК требует CAPTCHA, подтверждение входа или отказывает по правам — показывает соответствующее сообщение, без обхода. Успешную работу с конкретным токеном и реальное воспроизведение нужно проверить на устройстве пользователя. Токен в чат/репозиторий не передавать.

## Защита данных

- Токен шифруется AES-GCM, ключ — Android Keystore. Безопасность не гарантируется на скомпрометированном/root-устройстве.
- Нет токена в URL запросов: `users.get`, `video.search`, `video.get` используют HTTPS POST на `api.vk.com`, перенаправления этих запросов запрещены.
- Токен не отправляется Shikimori, серверу разработчика, аналитике или видеосерверу. Запрос видеофайла получает только адрес, выданный VK; OAuth-токен к нему не дописывается.
- Сырой ввод не сохраняется в состоянии окна; autofill/персонализированное обучение IME отключены для поля. `FLAG_SECURE` запрещает обычные скриншоты/содержимое в последних приложениях. Экран входа скрывает текст.
- Автобэкап и перенос пользовательских файлов исключены. Кнопка «Удалить токен» удаляет локальный шифротекст и ключ. Для отзыва прав на сервере нужно отозвать разрешение соответствующего приложения в самом VK.
- Нет фоновой синхронизации, сбора телеметрии, доступа к контактам, SMS или файлам телефона. В основном манифесте указан INTERNET. После объединения библиотек итоговый APK также содержит ACCESS_NETWORK_STATE и внутреннее сигнатурное разрешение DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION от AndroidX; это не доступ к контактам, файлам или сообщениям.
- Никаких ключей подписи и настоящих токенов в исходном ZIP. В тестах используются искусственные строки.

## Что НЕ входит в прототип

Нет скачиваний, общего календаря, личной коллекции, переноса истории YORU и автоматического соответствия ID Shikimori ↔ ID видео VK. У разных загрузок могут быть неверные названия, другая озвучка, нарезка, реклама или удалённое видео. Проверяйте результат и используйте контент, который вправе смотреть.

Номер сезона — редактируемая подсказка для поискового запроса, а не достоверное поле Shikimori. Связанные сезоны открываются отдельными карточками. При пересоздании главной Activity восстанавливается запрос каталога, но не весь стек карточка/результаты; постоянная история просмотра в 0.1.0 не заявляется. Позиция текущего плеера сохраняется при пересоздании его Activity, но не как библиотека истории.

Нет RAM-кэша изображений, самостоятельного дискового/HTTP-кэша или фонового предзагрузчика в новом приложении. Изображения декодируются для отображения, UI держит текущую выдачу; это не обещание «приложение не использует оперативную память». Встроенная буферизация Media3 необходима для воспроизведения. Кэш и код основной YORU вообще не изменялись.

## Сборка

Java 17, Android SDK 36, Gradle 8.13, AGP 8.13.2, minSdk 26 / Android 8.0+, Media3 1.5.1.

```
cd yoru-vk-android
chmod +x gradlew
./gradlew :app:testDebugUnitTest :app:assembleRelease
```

Выход: `app/build/outputs/apk/release/app-release.apk`.

**Подпись тестовая, отдельная от YORU.** Release-вариант не debuggable, но для этого первого прототипа подписывается автоматически созданным debug-ключом CI. Это не production-подпись. На другом runner ключ может отличаться: последующий прототип может потребовать удалить прежний YORU VK и ввести токен заново. Для стабильного канала обновлений отдельно настроить постоянный ключ. Установленную основную YORU это не затрагивает.

## Проверка

Unit tests проверяют токены/ссылки, составление запросов, границы номеров серий, разбор Shikimori, дедупликацию видео, допустимые прямые потоки и ошибки прав. Это не авторизованный end-to-end тест ВК.

CI дополнительно проверяет подпись, applicationId, версию и отсутствие `debuggable`, пробует публичный Shikimori запрос для ID 11757 и сохраняет `handoff/YORU-VK-0.1.0-build.json`. Итог конкретной сборки смотрите в этом JSON, не в предположении о результате.

## Быстрый сценарий на телефоне

1. Установить отдельный APK и убедиться, что YORU осталась на месте.
2. Открыть «Мастера меча онлайн»; дождаться каталога Shikimori и выбрать нужный тайтл/сезон.
3. Ввести сезон 1, серию 1, при необходимости озвучку; нажать «Смотреть · найти видео ВК».
4. Ввести свой токен через «ВК +», проверить аккаунт. Токен вводится только здесь.
5. Проверить результат поиска и открыть подходящее видео. Если `files` нет — зафиксировать только текст/код ошибки, без токена.
6. Проверить паузу, перемотку, качество, возврат, фон/возврат и поворот телефона.
7. Для отчёта достаточно сообщить, на каком шаге ошибка и её код. Полную ссылку токена не присылать.
