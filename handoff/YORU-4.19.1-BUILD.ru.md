# YORU 4.19.1 — исходники, сборка, проверки

Дата: 2026-09-09. Продолжение 4.19.0 от стабильной базы 4.17.2. Версия 4.19.1 / 70.
Ветка: `arena/01a0828d-animmmemmemwm`.

## Исправления

В прежнем airingSchedule общий fallback проверял пустоту списка после добавления избранного. При сетевой ошибке избранное могло сделать список непустым и выключить резервную загрузку общих событий. Теперь общий запрос и REST fallback выполняются до добавления избранного; личные данные не определяют необходимость резервного общего запроса. При отсутствии общих данных личный fallback помечен как неполный.

Фильтр календаря возвращается к «Все / Все дни» при входе на вкладку. Весь полученный список доступен в одном RecyclerView; искусственная выдача первых пяти удалена. Точность расчётных дат не повышалась искусственно: прежние пометки «Расчёт / Скоро» сохранены.

Большая кнопка будущих загрузок удалена. Ожидающие задания показаны обычными карточками в общем списке: постер, серия, озвучка, качество, дата/статус, кнопка отмены (корзина). Это не фиктивно завершённая загрузка: play и прогресс скачивания не показываются. После принятия реальной загрузки план не дублируется. Удалённая ранее скачанная серия не возвращается как ожидающий план.

## Кэш и ограничения

MediaCache, YoruCache и ImageLoader побайтово совпадают с 4.19.0. Нет новых RAM-кэшей, изменения TTL/лимитов или очистки сохранённых данных. Первое открытие календаря и явная кнопка обновления запрашивают актуальные данные, сохраняя показ прежних данных до ответа.

Работа всех внешних источников не гарантируется: прямой сетевой запрос Shikimori из sandbox закончился TLS EOF. Исправлена доказанная логическая ошибка, но региональную доступность нужно проверить на телефоне. При недоступности всех общих API нельзя обещать «все события»; UI указывает частичный личный результат. Расписание ограничено прежним горизонтом 28 дней и доступностью метаданных источника.

JobScheduler для будущих скачиваний, выбранная озвучка/качество, интервалы и ограничения Android не менялись. Сторонние приложения и VK Cloud изучаются только для предложений, не подключены.

## Сборка

Java 17, Android SDK 36, build-tools 36.0.0.

```sh
cd yoru-android
chmod +x gradlew
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

Release подписывается существующим ключом в прежнем CI, без смены подписи. В новом исходном ZIP нет приватных signing-файлов. CI для release зависит от существующего репозиторного signing input; автономная debug-сборка его не требует.

```sh
python tools/check-yoru-update.py
python tools/package-yoru-source.py
sha256sum -c handoff/YORU-4.19.1-source.zip.sha256
```

## Регрессионная проверка

Unit tests: общий запрос падает при непустом избранном; пустое избранное; частичная общая ошибка; личный запрос падает при успешном общем; полный отказ; 120/550 событий не обрезаются до пяти; ожидающий план показан, принятый download не дублируется, удалённый переданный план не появляется вновь.

На устройстве дополнительно проверить: календарь с пустой/непустой коллекцией; выбрать «Избранное», уйти и вернуться → «Все»; прокрутить полный список; явное обновление после восстановления сети; отменить план; переход карточки из будущей в реальную загрузку; уход с экрана во время refresh. Физическое устройство и эмулятор в этой среде не использовались.
