## 3. Что действительно делает APK с видео

### 3.1 Поиск — VK API с сессией, не обход авторизации

`java/ea4.java`, метод `h()`:

- `video.search`, `q`, `count=30`, `offset=page*30`;
- фильтры sort/hd/date/live/longer/shorter/type;
- DTO `com.vk.sdk.api.model.VkVideoArray`.

`java/i64.java` и `org/xjiop/vkvideoapp/auth/models/AuthModel.java` показывают работу VK SDK с авторизационной сессией/access_token. Наличие такого поиска в чужом APK не предоставляет нашей YORU его прав и не доказывает работу любого клиентского приложения без авторизации.

**Вывод:** взять структуру фильтров и пагинации можно как идею; переносить чужую идентичность OAuth, ключи или обещать поиск без входа нельзя.

### 3.2 Источники плеера и реальные качества

`java/com/vk/sdk/api/model/VKApiVideo.java`, участок `files`:

- варианты `hls_fmp4`, `hls`, `hls_ondemand`, `hls_live`;
- `mp4_2160`, `mp4_1440`, `mp4_1080`, `mp4_720`, `mp4_480`, `mp4_360`, `mp4_240`, `mp4_144`.

`java/org/xjiop/vkvideoapp/videoplayer/models/PlayerDataModel.java`:

- отдельные состояния preferHLS, autoHLS, brokenHLS;
- текущий URL/качество, выбор HLS или MP4;
- `setMP4QualityList()` добавляет уровень только при непустом URL.

`PlaybackService`, `CustomPlayerView`, `PlayerTimeBar` и связанные обфусцированные классы используют Media3. В `r94.M0()` есть блокировка управления с отдельной разблокировкой. Парсер HLS в `nj1` — библиотечная реализация Media3, не уникальный секретный extractor.

**Для YORU:** модель реальных вариантов, надёжный fallback и native player; не показывать 144p/240p/4K без соответствующего источника. Собственный существующий рисунок звезды и палитру не менять.

### 3.3 Важнейшее уточнение: собственный загрузчик не скачивает HLS

В ресурсах APK есть `@string/download_about_info` (ID 2131951936). Его русский текст прямо сообщает:

> Загрузка HLS возможна только с помощью сторонних приложений, для этого используйте «Открыть с помощью…».

Это согласуется с рассмотренным собственным загрузчиком:

- `DownloadsService` — очередь, уведомления, pause/resume/stop, foreground service;
- `DownloadsModel` — total/downloaded, status, errorCode, parts, threads, path, url;
- `ar0` — HandlerThread для задания;
- `xq0.e()` — HEAD;
- `xq0.g()` — HTTP Range;
- `xq0.k()` — работа с ContentResolver/ParcelFileDescriptor, fstat/ftruncate, разбиение файла на диапазоны;
- `vq0.c()` — проверка HTTP 206, чтение блоками, `Os.pwrite`, счётчики частей и сохранение прогресса.

`g7` также экспортирует M3U-плейлист из готовых видеоссылок. **Это не равнозначно скачиванию всех HLS-сегментов офлайн.**

**Для YORU:** полезны состояние задания, отмена, range-resume, SAF и контроль свободного места. Нужна независимая реализация с проверкой Content-Range/ETag и последовательным fallback, если сервер/SAF-провайдер не поддерживает random access. Наш существующий native Media3 offline-механизм нельзя заменять внешними ADM/1DM или незаметной конвертацией HLS в MP4.

### 3.4 «Перехват HLS» не подтверждён по одному имени метода

Все классы с найденными ключевыми callbacks просмотрены по контексту:

- `rz5` / `ez5`: AdWebView, mraid.js, рекламные запросы;
- `lm5`: wrapper WebViewClient;
- `ls5`: consent:// и Google consent SDK;
- `yads/ea3`: рекламный стек;
- Chromium boundary interface — библиотечный интерфейс.

Это нельзя выдавать за готовый универсальный extractor VK. Реальный путь видеоссылок выше идёт через DTO `files` VK API. В APK также обнаружена отдельная обработка сертификатов в `yd4`, включая условный `proceed()` после собственной проверки — не переносить её в YORU и не отключать обычную TLS-проверку.

Рекламу, аналитику, посторонние разрешения, DLNA/external-player поведение и авторизационные секреты в YORU не переносить.

## 4. Архив Animetka

Root-архив побайтно совпадает с ранее выданным handoff-архивом:

`1d329a7f848fca00ffd16a888e828a0c843f8d2e911de4d9debc5cdaf7b8d172`.

90 файлов: мобильные HTML/PNG/JSON/TXT-снимки, `index-DD8JNovU.js` и `index-DLq25J_f.css`. Собранный JS содержит Vue-компоненты; исходный backend и полноценный проект разработки в архиве отсутствуют.

Изученные соответствия:

- топовый поиск сортирует по `shikimori_rating`;
- `InfiniteSearchCheckboxList` и `/api/anime/genres?query=…` — поиск/пагинация жанров, а не только 20 видимых в одном снимке;
- `PlayerInline` — inline-панель, выбор озвучки и серии;
- favorite_voices поднимаются в списке по предпочтениям пользователя;
- история/поисковые предложения связаны с тайтлами и карточками;
- фильтры: несколько жанров/озвучек/типов, диапазон лет, минимальная оценка.

В разобранном frontend нет основания считать порядок favorite_voices статистикой просмотров Shikimori.

Не переносить ошибки сайта: в снимке Re:Zero TV4 показаны метаданные первого сезона и странное соотношение «25 / 19»; это пример того, почему нельзя соединять сезоны только по текстовому названию. Сохраняем native player и цвета YORU, берём только UX-идеи и независимо реализуем связи по идентификаторам.

## 5. Проверка спорных требований

### Просмотры озвучек

Проверен официальный `Types::AnimeType` Shikimori: есть `fandubbers`, `fansubbers`, `episodes`, `episodes_aired`, `next_episode_at`, `chronology`; поля просмотров каждой озвучки в рассмотренной схеме нет.

Источник: https://github.com/shikimori/shikimori/blob/a900114c48be8fdbc212139017b18e81a1c9a76f/app/graphql/types/anime_type.rb

Нельзя показывать придуманное «123 456 просмотров AniDUB» как данные Shikimori. Рейтинг аниме и статистика озвучек — разные вещи.

### Точный размер

HEAD/Content-Length или корректный Content-Range могут дать длину конкретного файла. Они не дают автоматически полный размер HLS master: есть выбранные video/audio playlists, init segments, byte ranges, меняющиеся live playlists и иногда неизвестные длины. В таких случаях честный результат — «размер неизвестен», а не точная на вид оценка.

### OkHttp и SDK37

- Официальный changelog OkHttp указывает **5.5.0 от 16.08.2026**. Репозиторий square/okhttp перенаправляет на lysine-dev/okhttp; это проверено GitHub API. Версия включает изменения DNS/ECH; дополнительный DNS/RAM-кэш в YORU автоматически не включать. [1](https://github.com/square/okhttp/blob/master/CHANGELOG.md)
- Официальная инструкция Android 17 указывает **compileSdk 37 / targetSdk 37**. Это подтверждение платформы, но не успешная установка SDK/сборка нашего проекта. [2](https://developer.android.com/about/versions/17/setup-sdk)
- При миграции проверить CT, MediaSession/background audio, системную навигацию и большие экраны: https://developer.android.com/about/versions/17/behavior-changes-17
