# YORU — идеи следующих обновлений, только после одобрения

Дата исследования: 2026-09-09. Ничего из этого списка не внедрено в 4.19.1.

Проверены публичные GitHub README, release notes, метаданные лицензий и доступность репозиториев. Это не полный аудит стороннего кода и не гарантия стабильности чужих функций. Сопоставление с YORU выполнено по активным MainActivity, PlayerActivity, SecureStore, FeaturePanels, manifest и текущим классам скачиваний.

## Проверенные проекты

### Aniyomi — `aniyomiorg/aniyomi`

В README указаны локальный просмотр, категории, трекеры, обновление библиотеки по расписанию и резервные копии в локальное/облачное хранилище. [1](https://github.com/aniyomiorg/aniyomi)

GitHub API: не архивирован; лицензия Apache-2.0; HEAD при проверке `4b5b90a3749b2c0504d4ffdd9416051d4730226c`.

**Что интересно YORU:** развить резервное копирование — не добавлять второй ручной экспорт, а сделать проверяемые автоматические копии коллекции, истории, настроек и будущих заданий. В YORU ручной JSON export/import уже есть; очередь будущих скачиваний в него пока не входит. Автоматичность и шифрование предлагаемой копии — наше предложение, а не утверждение, что именно такая схема реализована у Aniyomi.

### Anikku — `komikku-app/anikku`

README описывает межустройственную синхронизацию через SyncYomi/Google Drive, Android TV/Fire TV, экран ошибок обновления и миграцию записей с проблемных источников. Release notes отдельно показывают исправления update-errors и синхронизации. [2](https://github.com/komikku-app/anikku) [1](https://github.com/komikku-app/anikku/releases)

GitHub API: не архивирован; Apache-2.0; HEAD `41fefe566a00e8eb38dfa7f11802c8bfbe5c16e7`.

**Что интересно YORU:**
- Действия над конкретной неработающей записью: повторить, выбрать соответствующий тайтл другого действующего источника, сохранить историю и номер серии.
- Отдельная адаптация под телевизор/пульт, а не просто установка телефонного APK.
- Необязательная синхронизация библиотеки между собственными устройствами.

В YORU уже есть automatic source fallback и приоритет озвучек. Предлагаемая миграция — не повтор этих механизмов, а явная операция переноса сохранённой записи с предварительным сопоставлением сезона/названия/номеров серий. Диагностика нужна только по запросу пользователя, не техническими надписями на главной и не возвратом удалённого раздела «Новые серии».

### Animeko — `open-ani/animeko`

README описывает облачную синхронизацию прогресса, расписание, поддержку Jellyfin/Emby и больших экранов. В release notes 6.0.0 заявлены совместный просмотр (syncplay), превью кадров на шкале и информация о воспроизведении. [3](https://github.com/open-ani/animeko) [4](https://github.com/open-ani/animeko/releases/tag/v6.0.0)

GitHub API: не архивирован; AGPL-3.0; HEAD `c1649287217d488f6dba162748f02b1555d0e345`.

**Что интересно YORU:** комната совместного просмотра, где синхронизируются play/pause/позиция, но видео у каждого запускается в нашем нативном плеере. Это не ретрансляция чужого видео через сервер комнаты. Нужны соответствие версии серии, обработка рекламы/разной длительности и явное управление ведущим. Автоматическую идеальную синхронизацию разных монтажей обещать нельзя.

**Что не предлагаю переносить:** торрент-движок, другой плеер, дополнительное кэширование, аппаратный апскейл и постоянно работающие тяжёлые визуальные эффекты. Они не соответствуют текущим ограничениям YORU и приоритету слабых телефонов.

## Приоритеты для согласования

| № | Наше предложение | Что добавится относительно YORU | Нагрузка/сложность | Рекомендация |
|---|---|---|---|---|
| 1 | Проверяемые резервные копии по расписанию | Включить будущие задания; контроль целостности; восстановление с предварительным просмотром; шифрование отдельным пользовательским секретом | Невысокая нагрузка, средняя сложность; файловый I/O по расписанию, не RAM-кэш | Сначала это |
| 2 | Восстановление проблемной записи | Понятное действие «Повторить / выбрать другой соответствующий тайтл» с сохранением прогресса | Невысокая фоновая нагрузка, сложность корректного matching | После стабильности календаря |
| 3 | TV/пульт | Фокус, D-pad, крупные зоны управления, управление нативным плеером без touch-жестов | Средняя сложность, тестирование на ТВ | Если реально нужен телевизор |
| 4 | Синхронизация своих устройств | Продолжить на другом телефоне/планшете; разрешение конфликтов прогресса | Средняя/высокая сложность, backend или отдельно выбранное хранилище | Только опционально |
| 5 | Смотреть вместе | Приглашение в комнату, ведущий, общая позиция | Высокая сложность, signaling backend, сетевые тесты | Не смешивать с ближайшим bugfix |

Оценки — инженерная приоритизация, не измеренные характеристики чужих приложений и не обещание сроков.

## Что уже есть и не выдаётся за новинку

В YORU уже есть: коллекция/папки, история, ручной export/import, auto-next, пропуск заставки, таймер сна, PiP, offline HLS/DASH, массовые скачивания, предпочитаемые озвучки, календарь и будущие скачивания. Простое наличие этих функций у другого проекта не основание переписывать наши реализации.

## Лицензии и ограничения

Идеи UX можно реализовать самостоятельно. Копирование исходников, ресурсов и зависимостей требует отдельной проверки лицензии конкретного файла/версии; Apache-2.0 требует соблюдения условий уведомлений, а AGPL-код нельзя считать свободным от copyleft-обязательств. Юридическую совместимость всей сборки при заимствовании нужно проверить отдельно. В этот выпуск сторонний код не копировался.

AniList не возвращать. Не добавлять API-key-зависимые аниме-источники, VPN, proxy, новый плеер или RAM-кэш. Для облачной синхронизации сначала согласовать способ аутентификации и обработку персональных данных, а не включать её по умолчанию.

Miru дополнительно проверялся через GitHub API: запрос репозитория `ThaUnknown/miru` вернул HTTP 451 / Repository access blocked (DMCA). Поэтому его текущий исходный код не анализировался и рекомендации на старых пересказах Reddit не строятся.

**Нужное решение пользователя:** выбрать конкретные пункты. До этого — только этот документ, без реализации.
