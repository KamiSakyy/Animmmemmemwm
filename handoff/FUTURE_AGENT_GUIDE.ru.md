# Памятка будущему агенту YORU

Текущий продукт: Java Android `app.yoru.mobile` в `yoru-android/app`, актуальная линия 4.12.7. Kotlin удалён из активной сборки и не должен возвращаться без прямой команды пользователя.

Говорить с пользователем на русском. Пользователь хочет видеть этапы и проценты: коротко писать, что делается, без молчания на долгих шагах.

## Срочное исправление 4.12.7

После 4.12.6 пользователь снова указал проблемы: календарь фактически показывает только пару аниме/событий, видна грубая полоса прокрутки, на главной появился технический текст вместо красивого anime preview, а в загрузках не хватает красивого preview/video-preview.

Что сделано:

- `CalendarScreen` переписан на один верхнеуровневый `RecyclerView`.
- Header, hero, дни, фильтры и события теперь элементы одного adapter, без `ScrollView + nested RecyclerView`.
- Default `selected = -1`, то есть календарь открывается в режиме `Все`, а не в одном выбранном дне.
- `dayItems(-1)` собирает события всех 28 дней и сортирует по времени.
- День-чипы остались ручными фильтрами только после нажатия пользователя.
- `ApiRepository.airingSchedule()` расширен: 8 страниц ongoing, 3 страницы anons, fallback до 120; для тайтлов без точной даты есть spread-слоты `Скоро`.
- `YoruApp` прогревает календарь на 28 дней.
- Системные scrollbars скрыты в календаре, главной, деталях, плеере, списках и кастомных диалогах.
- Главная снова использует красивую hero/poster карточку с Фрирен и художественным описанием; технические app-change строки убраны.
- `DownloadsScreen` показывает крупную preview/poster карточку для скачанных серий; download service не трогался.
- Compile-fix: в `MainActivity.home()` hero-переменная переименована в `heroAnime`, чтобы не конфликтовать с локальными `Anime a` в циклах/lambda.

Не возвращать:

- nested calendar layout, который снова может ограничить видимый список двумя карточками;
- default календарь, ограниченный одним выбранным днём;
- стартовый loading/shell экран;
- надпись `Открываем без ожидания…` или аналогичные startup-заглушки;
- цифры/бейджи в нижней кнопке `Календарь`;
- грубые системные scrollbar-полосы;
- технический текст на главной вроде `Смотрите без лишних экранов`.

## Срочное исправление 4.12.6

После 4.12.5 пользователь резко указал три проблемы:

1. Нельзя показывать отдельный загрузочный экран/надписи при старте.
2. В нижней кнопке `Календарь` нельзя показывать цифры/буквы/бейджи (`Календарь · 3` и подобное).
3. Календарь не должен показывать только 1 день/2 аниме по умолчанию — нужен весь список, как раньше.

Что было сделано:

- Полностью удалён `showBootShell()` и текст `Открываем без ожидания…`.
- `MainActivity.onCreate()` снова сразу вызывает настоящий `render()`, без промежуточной заставки.
- Главная облегчена: первые видимые блоки строятся без обязательного синхронного `api.seed()`/`store` чтения, а рекомендации подставляются фоном.
- В `navigation()` удалён календарный счётчик из текста нижней кнопки. Там всегда должно быть просто `Календарь`.
- В календаре введён режим `Все`, а отдельные дни работают как фильтры.
- Из календаря убраны лишние loading-фразы, чтобы не было ощущения отдельной загрузочной заставки.

## Важное исправление 4.12.5

После 4.12.4 пользователь сообщил, что в календаре интерфейс “уехал”, скролл не работает и аниме не видно. 4.12.5 временно вернул `ScrollView`; в 4.12.7 это заменено на один верхнеуровневый `RecyclerView`, чтобы не было nested-scroll проблемы и обрезания событий.

Также по жалобе на долгий чёрный старт и задержки:

- `SecureStore` lazy: AndroidKeyStore и decrypt JSON не выполняются в конструкторе.
- `ApiRepository` lazy: `boot.json/counts.json` не читаются в `Application.onCreate()`.
- `TrafficMeter` не читает encrypted traffic-store на старте.
- `Ui.text()` больше не будит `SecureStore` ради шрифта/масштаба до готовности хранилища.
- Убраны startup `postDelayed` цепочки из `YoruApp`; задачи уходят в background executor без блокировки UI.
- Touch-анимации сокращены.

## Важное исправление 4.12.4

4.12.4 добавил крупный Java-only performance update: SQLite `YoruCache`, screen-cache вкладок, RecyclerView серий, fast offline-index, franchise-cache/filter/order, max hidden routes/threads. 4.12.5/4.12.6/4.12.7 исправили календарный layout/regression, startup shell, режим отображения календаря, hero главной и preview загрузок.

Если дальше править скорость: не возвращать full scans в render, не делать DownloadManager/SQLite/network на UI thread, не запускать repeated details по избранному календарю. Cache — только bounded/TTL/trim.

## Важное исправление 4.12.3

В 4.12.3 были сделаны: Calendar buckets по фильтрам/дням, кэш экземпляра `CalendarScreen`, двухступенчатая загрузка `DetailsActivity` через `quickDetails()`, вынос DownloadManager из UI-render, Shikimori franchise lookup, снятие лимита на связанные элементы в UI и turbo IO/discovery.

## Важное исправление 4.12.2

Главная причина лага после 4.12.1 была в горячих путях календаря и карточки: repeated `favorite()`/`progress()` сканировали JSON, Calendar → `Избранное` мог запускать тяжёлые последовательные details/search, а карточка серий проверяла DownloadManager для каждой строки. В 4.12.2 это исправлено быстрыми индексами SecureStore, cached-first календарём, batch/parallel schedule lookup и одним проходом по завершённым загрузкам. Не возвращать надпись `Загружаем список серий…` и текст про список серий `в фоне`. Само фоновое скачивание серий не трогать.

## Важное исправление 4.12.1

Не доверять техническим строкам серий выше `episodesAired`. Если известно `Вышло 15 из 25`, любые строки 16–25 должны стать future-заглушками, даже если скрытый источник заранее отдал для них URL-шаблон. В UI для таких серий нельзя показывать `Видео-превью`, постер, play или download.

Календарь `Избранное` не должен фильтровать по точному `source:id`: один тайтл может быть сохранён как YORU, Shikimori, AniLibria или другой источник. Использовать MAL/Shikimori/Anilist/KP ID и нормализованное название+год, а расписание избранных подмешивать отдельно к общему календарю.

## Важное исправление 4.12.0

Выбранная озвучка по умолчанию — это приоритет, а не причина падать. Если пользователь выбрал AniLibria.TV, но у тайтла/серии есть только другая реальная озвучка, YORU обязан скрыто обнаружить доступные голоса и открыть/скачать рабочий вариант. Нельзя завершать сценарий сообщением “серия недоступна” только из-за отсутствия выбранного голоса.

Карточки и детали должны показывать статус тайтла и прогресс выхода серий: `Вышло X из Y`. Для онгоингов нужно использовать индивидуальное расписание (`nextEpisodeAt`, если доступно), а невышедшие серии показывать как future-заглушки с датой/уточнением, без обычного play/download-вида.

## Главная цель проекта

YORU — удобное Android-приложение для просмотра аниме. Главные приоритеты: стабильность, скорость, минимализм, удобные серии, реальные озвучки, быстрые загрузки, сильный YORU и один нативный YORU Player.

## Озвучки

Нельзя считать внутренние маршруты озвучками. Озвучки — только реальные названия голосов/команд, которые пришли у конкретного аниме/серии: AniDUB, AniLibria.TV / AniLiberty, AniMaunt, AnimeVost, AniStar & DEEP, Beyond:Studio, Dream Cast, AniMedia, StudioBand, JAM, SHIZA Project и другие реальные названия.

Пользователю не показывать технические маршруты. YORU/Yummy/Kodik/AnixSekai/внутренние маршруты не должны называться озвучками.

## Маршруты и производительность

Пользователь явно попросил максимум мощности, потоков и маршрутов без дефолтного ограничения под слабые телефоны. Не возвращать mobile/data-saver урезание discovery/качества как default. При этом не делать бесконечные сетевые циклы: использовать дедлайны, cancellation и cache TTL.

Если маршрут ломается, YORU должен пробовать другой маршрут без вывода технической панели.

## Плеер

Один пользовательский плеер — нативный YORU Player. Не возвращать большие кнопки под видео и не включать стандартные ExoPlayer controls одновременно с YORU overlay. Fullscreen должен быть настоящим fullscreen/landscape без панелей приложения.

## Скачивание

Перед скачиванием показывать фильтры: доступные озвучки конкретной серии и 360p / 480p / 720p / 1080p / лучшее доступное. Выбранная озвучка и разрешение — быстрый приоритет; если выбранного варианта нет, скрытый fallback обязан найти доступный реальный голос/качество. Не ломать background download service.

## Что не возвращать

Не возвращать нерабочие направления, лишние центры, игровые счётчики, VPN-функции, конвертацию видео, старые отдельные категории маршрутов, бесполезные настройки и маркетинговые обёртки.

Запрещённые/отклонённые направления: Clips, “Ещё”, AniList как пользовательский источник, TSM, AnimeGO, JutSu, SameBand, SovetRomantica, Yummy Legacy, VPN/VLESS/Xray/proxy/private links, MP4 conversion.
