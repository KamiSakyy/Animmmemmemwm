## Что сделано

Главная просьба выполнена: во вкладке/режиме календаря **`Все`** приложение больше не рендерит весь список событий сразу. Оно показывает первые **5** событий, а при прокрутке вниз или кнопкой **`Ещё 5`** добавляет следующую порцию из **5**. Все данные календаря при этом остаются доступными: это не урезание расписания, а lazy-render для снижения лагов.

## 20 новых функций/улучшений

1. `Все` в календаре стартует только с первых 5 событий, чтобы не создавать тяжёлый первичный render.
2. При прокрутке вниз календарь добавляет следующие 5 событий через `notifyItemRangeInserted`, без полного пересоздания списка.
3. Добавлена кнопка `Ещё 5` внизу списка для ручной догрузки, если экран высокий и прокрутки пока нет.
4. Добавлен footer-прогресс `показано X из Y`, чтобы понятно было, сколько событий ещё скрыто.
5. Заголовок календаря теперь показывает `показано X из Y` именно для режима `Все`.
6. RecyclerView получил `DefaultItemAnimator` с короткими add/move/change animation — новые карточки появляются плавнее.
7. Чтение SQLite schedule-cache и legacy `calendarCache` перенесено в background executor, чтобы вкладка календаря открывалась без UI-паузы.
8. `quickShow()` больше не парсит кэш на UI-потоке; если данных нет, запускается обычная фоновая загрузка.
9. Персональные признаки `Избранное`/`Новые` не заставляют UI ждать `SecureStore`: если store ещё не прогрет, он догружается в фоне и календарь обновляется после готовности.
10. Внутри построения buckets добавлен memo favorite/history по anime key — повторяющиеся события не дёргают `SecureStore` заново.
11. Дубликаты событий от разных источников убираются по `anime/time/episode/kind`, чтобы список не раздувался.
12. Счётчики фильтров теперь кэшируются в `filterCounts`, а не пересчитываются сортировкой списка каждый раз.
13. Чипы фильтров показывают количество событий: `Все · N`, `Избранное · N`, `Скоро · N` и т.д.
14. Чипы дней показывают количество через прямой bucket-size, без лишнего `dayItems().sort()` для каждого дня.
15. Добавлена кнопка `К ближайшей` — быстрый переход к ближайшему будущему событию.
16. Если ближайшее событие дальше пятой позиции, календарь раскрывает нужное количество страниц и плавно скроллит к нему.
17. Карточки календаря получили цветовой акцент: премьеры, уже вышедшие, ongoing и обычные события визуально различаются.
18. В строке события добавлен мягкий suffix `в коллекции` или год, когда это доступно без тяжёлой загрузки.
19. Долгое нажатие на событие открывает добавление/перенос тайтла в коллекцию прямо из календаря.
20. Empty-state стал полезнее: для пустого календаря есть `Обновить`, для пустого фильтра — `Показать все`.

## Что не ломалось

- Основной интерфейс YORU не заменялся и не упрощался.
- Все фильтры календаря сохранены: `Все`, `Избранное`, `Новые`, `Скоро`, `Премьеры`, `Выходит`, `Фильмы`.
- Календарь по-прежнему охватывает 28 дней и отдельные дни можно открыть полностью.
- Сохранены улучшения 4.12.10: cold start без UI-blocking KeyStore/cache, concurrent HTTP cache, throttled SQLite trim.
- Сохранены улучшения 4.12.9: bounded executors, image dedupe, меньшие timeout'ы, отмена устаревших catalog/search задач.
- Сохранены фоновые уведомления 4.12.8: JobScheduler + AlarmManager fallback, boot/update/time reschedule, автономная проверка.
- Сохранены пользовательские UI-правки: нет startup loading shell, нет календарных badges в нижней навигации, красивый home hero, hidden scrollbars, downloads previews, реальные названия озвучек.
